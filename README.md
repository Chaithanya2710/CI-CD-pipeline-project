# Spring PetClinic CI/CD Pipeline

An end-to-end DevOps portfolio project documenting a Jenkins pipeline for the Spring PetClinic application.

> **Project note:** The original Jenkins servers were terminated, so the `Jenkinsfile` in this repository has been reconstructed from the available screenshots and notes. It is not a recovered copy of the original script and has not been re-tested against the original environment.

## Source application

Official source repository: https://github.com/spring-petclinic/spring-framework-petclinic

## Pipeline stages

1. Checkout the Spring PetClinic source from GitHub.
2. Compile with Maven.
3. Run tests.
4. Run SonarQube analysis.
5. Publish the Maven artifact to Nexus Repository Manager.
6. Copy the WAR artifact to Apache Tomcat over SSH.
7. Send a success or failure email notification.

## Before running

The `Jenkinsfile` contains environment-specific placeholders/configuration that must be checked before running:

- Jenkins tool names `JAVA_HOME` and `MAVEN_HOME`
- SonarQube installation name `SonarQube`
- Maven settings configuration ID `nexus-config`
- SSH credential ID `tomcat-cred`
- Tomcat host, deployment path, and notification email
- Git branch and the actual WAR filename generated by Maven

The pipeline uses `sh`, `scp`, and `sshagent`, so it expects a compatible Unix/Linux Jenkins agent and the required Jenkins plugins. Confirm the repository's actual default branch and build output before running.

**Security:** Do not commit passwords, access tokens, private keys, or unredacted sensitive server details. Store credentials in Jenkins Credentials and redact screenshots before publishing.
